# 如何为《浮屿》贡献一座新岛

岛屿内容全部存放在 `data/worlds.json`，是纯数据，不需要会写代码也能参与。

## 岛屿 JSON 结构

```json
{
  "id": "唯一英文 id，如 wu-feng-zhi-hai",
  "name": "岛名，如 静默屿",
  "rule": "这座岛的规则，一句话写清，克制、不解释",
  "start": "起始场景 id",
  "scenes": {
    "scene-id": {
      "text": "场景描述",
      "fragment": { "id": "唯一碎片 id", "text": "碎片内容" },
      "choices": [
        { "label": "选项文字", "to": "下一场景 id" }
      ]
    }
  }
}
```

- 一个场景可以没有 `choices`，它就是这个岛屿的终点。
- `fragment` 只在首次进入该场景时收入碎片。
- 场景之间用 id 互相跳转，形成一张有向图；请保证每个可达场景最终通向终点。
- 完整示例直接看 `data/worlds.json` 里的「静默屿」。

## 一条好规则的检查清单

- [ ] 一句话能说清，不需要额外解释
- [ ] 与这座岛的故事互为因果（规则是故事的形状，不是装饰）
- [ ] 玩家可以靠自己观察出来，而不是被直接告知
- [ ] 至少有一个"没理解规则"的弯路场景，让失败本身成为提示
- [ ] 碎片内容关乎"我是谁 / 家在哪"，而不是解释剧情

## 提交流程

1. Fork 本仓库
2. 在 `data/worlds.json` 的 `worlds` 数组中追加一座岛
3. 在 `docs/ROADMAP.md` 的贡献记录里加一行
4. 提 Pull Request，说明：岛名、规则、你想让玩家感受到什么

Review 时我们会重点看：规则是否自洽、氛围是否到位、碎片是否动人。
